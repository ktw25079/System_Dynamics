# 재현 절차

## 실행 환경

최종 텍스트 모델의 헤더는 RecurDyn 2023 `10.1.40231.2023.10106`입니다. Windows에서 해당 모델을 열 수 있는 RecurDyn과 유효한 라이선스가 필요합니다. 다른 버전의 호환성은 확인하지 않았습니다.

저장소를 받은 뒤 `model/`을 작업용 폴더에 복사하고 `.rdyn`을 여세요. 원본 모델 파일을 변경하지 않고 작업 사본을 저장하면 기존 결과와 비교하기 쉽습니다.

## 모델과 파라미터

1. `model/SystemDynamics_UR3_pick_place_screw_bearing.rdyn`을 엽니다.
2. UR3의 Base–Wrist3 링크, 단일 강체 그리퍼, 스크류, 베어링, 테이블, 베어링 홀더가 있는지 확인합니다.
3. J1–J6의 Motion이 STEP expression을 사용하고, 물체 hold/grip/guide 구속의 OnOff 조건이 유지되는지 확인합니다. 최종 모델에 새 접촉 요소를 임의로 추가하면 보관 결과와 달라집니다.
4. `data/pp_waypoints.csv`에서 물체별 핵심 위치를, `data/joint_table.csv`에서 20개 상태의 시각과 조인트 각도를 확인합니다. PP는 작업 위치를 설명하는 데이터이며, PP 값만 고쳐도 이미 저장된 STEP expression이 자동으로 갱신된다고 가정하면 안 됩니다.

단위는 길이 mm, 질량 kg, 힘 N, 시간 s입니다. 중력은 Z 방향 `-9806.65 mm/s²`입니다. 원시 Request의 모멘트는 N·mm이므로 N·m 표시에는 1000으로 나눕니다.

## Dynamic Analysis

| 항목 | 최종 보관 설정 |
|---|---|
| 종료 시각 | 18.5 s |
| 결과 샘플 수 | 901개 (시작/종료 포함) |
| 적분기 | ADVHYBRID |
| 최대 내부 적분 간격 HMAX | 0.001 s |
| 초기 간격 INITIAL_H | 0.000001 s |
| 적분 오차 설정 ERROR | 0.005 |
| KMAX | 2 |

종료 시간과 출력 간격을 설정할 때 900개 구간/901개 샘플을 목표로 하고, GUI의 Step 표시가 구간 수인지 샘플 수인지 확인하세요. 내부 적분 간격 HMAX와 결과 저장 간격은 다릅니다. 정확한 기존 출력 시각은 원시 `.req` 파일에 있습니다.

Dynamic Analysis를 실행한 뒤 메시지의 성공 종료 여부를 확인합니다. 기존 최종 실행은 2026-06-21의 성공 로그를 근거로 보관했습니다. 동일한 모형이라도 솔버 버전 및 수치 설정에 따라 결과가 조금 달라질 수 있습니다.

## 토크와 후처리

`REQ_TORQUE_J1`부터 `REQ_TORQUE_J6`까지 확인합니다. 이 모델의 Request는 각각 조인트 base marker를 reference marker로 사용합니다. 회전축 토크를 읽을 때 여섯 관절 모두 해당 좌표계의 TZ를 선택합니다.

저장된 원시 결과를 재계산하려면 저장소 최상위에서 실행합니다.

```bash
python3 scripts/postprocess_results.py
```

결과는 `results/`에 생성됩니다. 실제 동역학 해석 없이 기존 결과를 파싱하는 명령입니다. 재해석 결과를 비교하려면 원본을 보관한 뒤 스크립트의 CLI 도움말에 따라 새 Request/RMD 파일을 지정하세요.

## 보관 결과와 검증 범위

`results/solver/UR3_v81_clean_optimized.*`의 원래 이름은 출처 추적을 위해 유지했습니다. `model/`은 제출용으로 이름을 정리한 최종본입니다. `--check`는 보관 결과의 축·단위·토크 계산 일치 여부를 검사합니다. 다른 PC에서의 모델 실행과 솔버 재해석은 별도 검증이 필요합니다.
